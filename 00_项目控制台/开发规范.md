# Echo Insight 开发规范

1. 产品代码、测试、依赖清单和构建配置位于 `02_工程代码/`。
2. 根目录只允许 README、许可证与声明、Git 规则，以及 `setup-local.cmd`、`setup-local.ps1`、`setup-local.sh` 三个安装入口。
3. 公开项目文档只允许白名单中的导航、风险规则和 AI 输出协议；资源与过程材料不得进入公开分支。
4. 真实 `.env`、密钥、Token、Cookie、OAuth code、运行时 JSON、依赖目录、测试输出与构建产物不得提交。
5. 飞书权限过滤必须先于规则分析与 AI；默认产品路径不得写回飞书。
6. visitor 模式的用户模型 Key 只能在后端使用独立主密钥加密保存，不得复用飞书 App Secret；账号身份必须包含应用上下文。
7. 影响密钥生命周期的变更必须覆盖同账号跨会话 / 跨设备恢复、跨账号隔离、主动删除全 Session 失效、竞态与无明文泄露测试。
8. 提交前运行 `npm test`、`npm run typecheck`、`npm run build:frontend` 与 `git diff --check`；只按明确路径暂存，禁止使用 `git add .`。
9. 对外发布前必须审计当前树和完整 Git 历史；公开远端不得包含私有路径、真实环境文件或敏感提交说明。

当前源码部署以单个 Node.js 后端实例、持久可写运行时目录与同源 `/api` 代理为支持边界。多实例、高可用和主密钥自动轮换需要单独的存储迁移与安全评审。
