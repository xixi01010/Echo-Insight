# Echo Insight 项目规则

## 1. 项目定位

Echo Insight 是一个基于飞书数据和 AI 能力的项目风险观察工具。AI 是项目雷达，而不是项目驾驶员。

## 2. 数据与权限

- AI 只能读取用户明确授权范围内的数据，禁止跨项目读取。
- 权限过滤必须发生在 AI 分析之前。
- 权限设计采用最小权限原则；开发环境中的宽权限不代表正式产品权限方案。
- AI 输出必须继承源数据权限，不得因总结或分析扩大信息可见范围。

## 3. AI 行动边界

- AI 默认只读项目源数据，不允许自动修改项目事实。
- 允许生成可解释、可追溯的派生分析结果。
- 禁止修改任务、负责人、Deadline、项目文档、权限或删除数据。
- 禁止进行员工能力、员工态度或绩效判断。

## 4. 当前产品边界

- 匿名演示只使用合成数据与预生成解释，不登录、不读取飞书、不调用模型。
- 真实工作区必须通过飞书登录；未加入项目的用户只看到空状态，不继承维护者或其他用户的数据。
- 在线 visitor 模式只接受 DeepSeek / 千问官方预设与用户自己的 Key；自托管 server 模式由部署者在服务端配置 Provider。
- 在线用户 Key 以完整飞书应用身份隔离并在后端加密保存；退出登录不删除，主动断开才删除。
- 模型调用费用由 Key 所属的模型平台账户承担，不由 Echo Insight 收取。

## 5. 工程与运行时职责

- `02_工程代码/frontend/`：React + Vite 用户界面与匿名演示。
- `02_工程代码/backend/`：身份、项目权限、数据源、规则与 AI 编排。
- `02_工程代码/feishu-connector/`：七类飞书来源的显式、只读访问。
- `02_工程代码/ai-service/`：Provider 适配、输出协议与安全降级。
- `02_工程代码/functions/`：在线部署的同源 `/api` 代理。
- `02_工程代码/tests/`：自动化安全与产品回归。
- 生产运行时数据必须位于持久目录；真实 `.env`、账号密文、依赖和构建输出不得提交。

## 6. 公开与文档治理

- `00_项目控制台/PROJECT-CONTROL.md` 是项目入口。
- 公开项目文档只包括导航、风险规则和 AI 输出协议；其余创作、比赛、交接和过程材料保留在本地私有范围。
- 公开历史必须从白名单生成，不能通过普通删除提交掩盖旧历史中的私有路径。
- README 对当前能力、已知限制、第三方费用与部署责任的表述必须与代码一致。
- 已归档验证结果作为本地历史事实保留；公开资料不得复制真实凭据、租户数据或私有证据。
